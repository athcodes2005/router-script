# Source inventory and authority

The parent directory is the implementation source of truth. This page describes
what is present without copying credentials or generated build products.

## Primary shell implementation

- Startup and lifecycle: `bootstrap_router.sh`, `tunnel.sh`, `stop_tunnel.sh`.
- Health and authentication: `ensure_network.sh`, `login.sh`.
- Network configuration: `configure_dns.sh`, `configure_lan_ipv6.sh`,
  `configure_wifi.sh`.
- Routing policy: `google_wan_policy.sh`, `refresh_blinkit_dns.sh`, `game_mode.sh`.
- Operations: `install_cron_pipeline.sh`, `rotate_logs.sh`, `rotate_tunnel_ip.sh`,
  `update_from_git.sh`, `firewall_hook.sh`, `install_firewall_hook.sh`,
  `promote_staged.sh`.
- Diagnostics: `diagnose.sh`, `collect_diagnostics.sh`, `dns_flow.sh`,
  `monitor_game_network.sh`, `measure_load_latency.sh`.
- Transfer: `sync_to_router.sh`, `sync_from_router.sh`,
  `download_emergency_diagnostics.sh`.
- Shared helpers: `paths.sh`, `defaults.sh`, `lock.sh`.

## Rust implementation

`usque-rs-optimized/` contains the buildable source, manifest, lockfile,
toolchain configuration, tests, and license. Its module responsibilities
are mapped in [[systems/warp-client]].

- `Cargo.toml` and `Cargo.lock` define the reproducible Rust dependency graph.
- `.cargo/config.toml` records target-specific compiler settings.
- `Cross.toml` records cross-compilation image and target configuration.
- `clippy.toml` and `rustfmt.toml` define source-quality policy.
- `LICENSE.md` records the source license.
- `.gitignore` excludes generated target artifacts and platform noise.
- `tests/tunnel_mtu.rs` is the standalone packet/MTU integration suite.

The root `usque-rs` file is the deployed ARM64 binary. The optimized directory
also contains a deployment copy and ignored build output under `target/`.
`usque-rs-upstream-v0.1.0` is a rollback binary, not active source.

## Data and documentation

- `README.md` is the concise root entry point linking to `wiki-llm/wiki/index.md`.
- `blocked_sites.txt` and `warp_clients.txt` are legacy compatibility data.
- `google_domains.txt` and `google_service_ranges.txt` are active Google WAN
  policy data; the ranges file is generated by `tools/update_google_ranges.py`.
- `.github/workflows/ci.yml` defines GitHub Actions CI for shell, sandbox, and Rust tests.
- `tests/` holds Python regression tests: recovery functions, whole-script
  health runs in a stubbed sandbox (`tests/sandbox.py`), `sync_to_router.sh`,
  `update_from_git.sh`, SIGHUP handling, login, diagnostics, rotation, Google
  policy and ranges, LAN IPv6, and Blinkit DNS.
- `.claude/settings.local.json` contains local assistant permissions.

## Sensitive sources

`.env` stores campus login credentials and configuration overrides.
`config.json` stores the WARP private key, token, identity, and endpoints.
Their paths and expected modes are documented, but their contents are excluded.

## Generated and excluded material

The router creates `logs/` and `diagnostics/`; these are operational evidence,
not canonical source. `.DS_Store`, Cargo `target/`, and packet captures are not
part of project knowledge. Imported user-provided references are kept under
`raw/assets/` and must remain immutable after import.

## Blinkit DNS maintenance

`refresh_blinkit_dns.sh` maintains IPv4-only records for the three observed Blinkit
API endpoints and installs corresponding WAN routes before exposing answers.
It is called by DNS setup, tunnel startup and the existing health pipeline.
Regression tests are in `tests/test_blinkit_dns.py`.
