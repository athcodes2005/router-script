# Top-level script and file map

## Runtime scripts

- `paths.sh`: chooses persistent log/diagnostic paths, falling back to `/tmp`
  when the project filesystem is at least 97 percent used or unwritable.
- `defaults.sh`: every default that more than one script uses; sourced after
  `.env`, so `.env` wins.
- `lock.sh`: the maintenance lock, with an owner record (PID, start time,
  uptime, name); never taken from a live owner by age.
- `firewall_hook.sh`: fw3 include that starts a health check right after fw3
  rebuilds the firewall.
- `login.sh`: probes connectivity and performs safe IITB portal login recovery,
  with curl `--resolve` pins for portal/SSO when campus DNS is unavailable.
- `tunnel.sh`: starts or reuses WARP and installs full-tunnel routing state.
- `stop_tunnel.sh`: terminates WARP with a bounded wait and restores direct WAN.
- `configure_wifi.sh`: applies the India regulatory domain and stable widths.
- `configure_dns.sh`: configures dnsmasq, campus forwarding, portal/SSO
  `address=` pins, and dnscrypt-proxy2 on `127.0.0.1#5453`.
- `configure_lan_ipv6.sh`: configures ULA-based LAN IPv6, RA, SLAAC, and DHCPv6.
- `ensure_network.sh`: serialized health checks, drift repair (including DNS
  pin and dnscrypt listen checks), recovery, fallback. Honors game-mode marker.
- `game_mode.sh`: prefer direct WAN for low-latency gaming; demote WARP default.
- `bootstrap_router.sh`: one-shot boot pipeline for config, login, and WARP.

## Operations scripts

- `install_cron_pipeline.sh`: installs staggered twice-per-minute health,
  15-minute Git updater, and periodic maintenance jobs.
- `update_from_git.sh`: polls `DEPLOY_BRANCH` on GitHub, verifies CI check-runs,
  promotes under `lock.sh`, gates on `ensure_network.sh`, and rolls back on failure.
- `fetch_usque_rs.sh`: fetches and SHA-256 verifies the `usque-rs` release binary
  from `USQUE_REPO` (`athcodes2005/usque-rs-openwrt`), backs up the previous
  binary to `usque-rs-upstream-v0.1.0`, promotes under `lock.sh`, and rolls back
  if the health check fails.
- `rotate_logs.sh`: bounds logs by size and retention count.
- `rotate_tunnel_ip.sh`: registers a new WARP identity with verified rollback.
- `sync_to_router.sh`: staged deployment with a SHA-256 manifest and bounded
  SSH/SCP sessions; `promote_staged.sh` then promotes the set on the router
  under the lock.
- `install_firewall_hook.sh`: registers the fw3 include `firewall.router_script`.
- `sync_from_router.sh`: bounded, staged, validated pull of mutable router state.
- `download_emergency_diagnostics.sh`: bounded remote capture and download.

## Diagnostic scripts

- `diagnose.sh`: captures carrier, radio, readiness, route, DNS, firewall, and
  exact direct/WARP connectivity state without reading secret files.
- `collect_diagnostics.sh`: writes uniquely named snapshots and enforces retention.
- `dns_flow.sh`: displays resolver configuration and tests important lookups.
- `monitor_game_network.sh`: read-only, bounded latency monitor for game
  sessions (optional `PHONE_IP`); logs via `paths.sh`.
- `measure_load_latency.sh`: round trips through WARP idle and under upload and
  download load (`logs/latency.log`), each run labelled with the client's
  upload-queue options; holds the lock, changes nothing.

## Data and executable files

- `.env`: secret credentials plus optional interface and policy overrides.
- `config.json`: secret WARP registration and tunnel addressing.
- `blocked_sites.txt`: legacy per-destination bypass data.
- `warp_clients.txt`: legacy per-client WARP selection data.
- `usque-rs`: active ARM64 OpenWrt executable.
- `usque-rs-upstream-v0.1.0`: inactive rollback executable.

## Documentation and local metadata

- `README.md`: short entry point linking to `wiki-llm/wiki/index.md`.
- `wiki-llm/`: all architecture, system, operations, and historical audit docs.
- `.github/workflows/ci.yml`: GitHub Actions CI for shell, sandbox, and Rust tests.
- `.claude/settings.local.json`: local tool permission configuration.
- `logs/.gitkeep`: preserves the local logs directory in version control systems.

## Blinkit DNS maintenance

`refresh_blinkit_dns.sh` maintains IPv4-only records for the three observed Blinkit
API endpoints and installs corresponding WAN routes before exposing answers.
It is called by DNS setup, tunnel startup and the existing health pipeline.
Regression tests are in `tests/test_blinkit_dns.py`.

## Google WAN policy

`google_wan_policy.sh` maintains direct-WAN destination policy and Google IPv6
fallback. `google_domains.txt` supplies DNS suffixes; `google_service_ranges.txt`
is generated by `tools/update_google_ranges.py`. See [[google-wan]].
